## 🔄 Последовательность инициализации

### При загрузке игры:

```
1. Загрузка HTML файла (game.html, olympus.html и т.д.)
   └─▶ <script src="auth.js"></script> загружен
   └─▶ <script src="admin.js"></script> загружен
   └─▶ <script src="game.js"></script> загружен

2. DOMContentLoaded event
   └─▶ init() вызван в game.js

3. checkAuth() выполнен
   ├─▶ Проверка lucybliss_current_user
   ├─▶ Если нет → redirect на auth.html
   └─▶ Если есть → продолжить

4. updateUserProfile(user)
   └─▶ Обновление UI (аватар, имя, ID)

5. Загрузка баланса
   └─▶ balance = user.balance

6. Инициализация игры
   └─▶ updateBalance(), createGrid() и т.д.

7. Игрок делает ставку
   └─▶ balance изменяется
   └─▶ saveUserBalance(balance)
       └─▶ Обновление localStorage
           ├─▶ lucybliss_current_user
           ├─▶ lucybliss_users[index]
           └─▶ userBalance (совместимость)
```

## 🔌 API функций

### UserManager (auth.js)

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `register()` | username, password | `{success, user, message}` | Регистрация нового пользователя |
| `login()` | username, password | `{success, user, message}` | Вход в систему |
| `logout()` | - | void | Выход из системы |
| `updateUser()` | userId, updates | boolean | Обновление данных пользователя |
| `getUser()` | userId | User \| undefined | Получение пользователя по ID |
| `getAllUsers()` | - | Array<User> | Получение всех пользователей |

### Игровые функции (game.js, olympus.js и т.д.)

| Функция | Параметры | Возвращает | Описание |
|---------|-----------|------------|----------|
| `checkAuth()` | - | boolean | Проверка авторизации при загрузке |
| `updateUserProfile()` | user | void | Обновление UI профиля |
| `saveUserBalance()` | balance | void | Сохранение баланса с синхронизацией |

### Админ-панель (admin.js)

| Функция | Параметры | Возвращает | Описание |
|---------|-----------|------------|----------|
| `initUsersSection()` | - | void | Инициализация секции пользователей |
| `loadUsers()` | - | void | Загрузка и отображение таблицы |
| `editUser()` | userId | void | Открытие модального окна |
| `saveUser()` | - | void | Сохранение изменений |

## ✨ Преимущества архитектуры

1. **Простота** - все на клиенте, нет сервера
2. **Быстрота** - мгновенные операции
3. **Автономность** - работает офлайн
4. **Синхронизация** - данные доступны везде
5. **Модульность** - легко добавлять новые игры

## ⚠️ Недостатки

1. **Безопасность** - все данные доступны из консоли
2. **Масштабируемость** - localStorage ограничен 5-10 МБ
3. **Мультиустройство** - нет синхронизации между устройствами
4. **Бэкапы** - данные могут быть потеряны
5. **Конкуренция** - проблемы при одновременном доступе
